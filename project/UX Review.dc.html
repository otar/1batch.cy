Usability review · 9 October 2026 · desktop and phone

1batch.cy: the first file, with no help

Goal: a bookkeeper opens the page for the first time and makes a correct 1bank file without reading help. I tested the page with an empty file, the example data, errors, an opened old file and a paste. Below are 8 changes, with the biggest gain first.

Users: accountants and bookkeepers who know 1bank, SEPA and BIC. They make a batch every month, from typing, Excel, a CSV export or last month's file. Method: Nielsen's 10 heuristics (H1–H10) and Krug's “Don't make me think”.

1

Say what the page does, and offer three ways to start

Gain high · Effort M · H6 recognition, not recall · H10 help · your note 1

What users see

  • The first screen is a form. It does not say what the result is, or how it saves work.
  • The tagline “Batch payment files for Bank of Cyprus 1bank” names the file, not the gain.
  • Two of the three ways to start are hidden. Paste is a grey sentence under the list. “Open file” does not say which files. Drag and drop has no sign.
  • Three “Add payment” buttons show at the same time. “New file” on an empty page does nothing.

The fix

  • Tagline with the gain: “One file for all your payments. Upload it once in 1bank.” Plus “Free and open source”.
  • Three steps above the form: add, download, upload. They go away when the list has data.
  • An empty list shows three start cards: paste from Excel (with a paste box), open last month's file, type. Plus “See an example”.
  • One way to add a row. “New file” shows only when there is data.

2

Show less in the payment list

Gain high · Effort M · H8 minimalist design · H7 efficiency · your note 2

What users see

  • Each payment has two lines and ten controls: checkbox, handle, four cells, type label, bank line and three icons. 30 payments give 300 things to scan.
  • You marked these as too much: search, column sort, the type and bank line under each IBAN, and the “More” line.
  • A click on a column name sorts the payments. This also changes their order in the file, and nothing says so.
  • With Tab, each row has 6 extra stops between the cells.

The fix

  • One line for each payment: number, name, IBAN, amount, description.
  • A green ✓ in the IBAN cell for a valid IBAN. The bank and the type show only while the cell has focus. A row shows its type only if you changed it.
  • The handle and the row actions show on hover and on focus. The actions are one Tab stop. The arrow keys move between them.
  • Remove search, column sort and the checkboxes. Delete rows one at a time, with Undo.
  • One “Add payment” row at the end. Enter in the last row also adds a row.
  • “Export CSV” moves to the header, next to “Open”. All file actions are in one place.

3

One main button that always says “Download XML”

Gain high · Effort S · H4 consistency · H1 status is visible

What users see

  • The main button changes its name and its job: “Add payment”, then “Show next error”, then “Download XML”. Users must read it again each time.
  • “Show next error” is a strange main action. Users want the file, not the errors.
  • On a narrow screen, the bar cuts the error text. “Look at 2 warnings” has no link.

The fix

  • The button always says “Download XML”. If there are problems, a click shows all of them and goes to the first one.
  • The bar gives the state in words. The button is green only when the file is ready.
  • Arrows go to the previous and the next problem. The bar has the short text. The row has the full text.
  • “1 warning” is a link to the warning. Warnings do not stop the download.

4

After the download, show the 1bank steps

Gain high · Effort M · H10 help · H1 status is visible · your 1bank screenshots idea

What users see

  • After the download, a small message says “Upload it in 1bank. Then approve it with Digipass.” It closes after 6 seconds.
  • The 1bank steps and the numbers to compare are one sentence in Help, far below.
  • Nothing says what to do if 1bank does not accept one payment. If users upload the full file again, the good payments go two times.

The fix

  • A panel opens after the download: the file name, the three numbers to compare in 1bank, and five steps with screenshots.
  • Step 5 says: if 1bank rejects a payment, make a new file with only that payment.
  • “Keep this file” points to change 5, for next month.
  • The same steps are in Help, for users who read first. The screenshots are image files, as you decided.

5

Next month: start from last month's file

Gain high for monthly users · Effort M · H7 efficiency · H1 status is visible

What users see

  • Each month, users change the amounts and the descriptions, and add or remove some payees.
  • They type the new month in each description by hand: “SEPTEMBER” to “OCTOBER” in every salary row.
  • After Open, a message says only “The execution date moved”. It closes after 10 seconds. A long amber note stays under the date.

The fix

  • After Open, a box above the list stays until you close it. It tells what the page opened and what changed.
  • In the same box: “Replace SEPTEMBER with OCTOBER in the descriptions”. The page finds the month name and suggests the next month. You can edit both words.
  • The words that change have a highlight before you click. Undo works for 10 seconds.
  • A tip for the amounts: Enter goes down the column.

6

Correct common errors with one click

Gain medium · Effort S · H9 recover from errors · H5 error prevention

Rejected before: auto-fix of characters and comma decimals. Here it is an offer that the user clicks. The page never changes data on its own.

What users see

  • Data from Excel and payroll programs often has “1,250.00”, “Ü” or “&”. The page finds the error, but users must type the fix in each cell.
  • The character message lists all allowed characters: 24 words to read in each row.
  • The paste preview does not tell that the amounts have thousands separators. The errors show only after the paste.

The fix

  • Under the error, a button with the exact new value: “Change to 1250.00”.
  • An offer only when the fix is sure. “1,250.00” gets a button. “1,250” does not: it can be 1250 or 1.25.
  • Two or more rows with the same kind of error get one button: “Change 6 amounts”.
  • A shorter message. The list of allowed characters stays in Help.
  • The paste preview says: “6 amounts have thousands separators. Remove them?”

7

Make “Pay from” shorter

Gain medium · Effort S · H8 minimalist design · H5 error prevention

What users see

  • Three hints tell accountants what they know: “As on the account. 70 characters maximum.”, “Default: next business day.”
  • The “More” line shows the BIC and the reference all the time. The debit account must be at Bank of Cyprus, so the BIC is always BCYPCY2NXXX. The field has no use.
  • The date shows in the browser format: 12.10.2026 here, 10/12/2026 in US English. There is no weekday.

The fix

  • The rule goes in the label: “Debit account (Bank of Cyprus IBAN)”. No hints. A limit shows only when the text is too long.
  • Under the date, the date in words: “Monday 12 October 2026”. A Saturday or a Sunday shows in amber.
  • Remove the BIC field. The page keeps the BIC from an opened file.
  • The reference moves to one quiet line: “File reference K7QP9F · Change”.

8

Help and privacy: a new layout

Gain medium · Effort M · H8 minimalist design · H10 help · your open question

What users see

  • Two long columns of grey text. Every item has the same weight, so nothing stands out.
  • The 1bank steps are one sentence in “How to send”.
  • The privacy claims are true, but a user cannot test them in one minute.

The fix

  • Three directions, in a separate file. All three have the 1bank steps with screenshots, shorter text, and a privacy test that takes one minute.
  • The test: “Turn off Wi-Fi. The page still works.” Users can see that nothing goes to a server.

Smaller findings

No mockups. Each one is a small change.

First visit and trust

  • The page asks for IBANs, but the top does not say who made it. The disclaimer is in the footer. Fix: also put “Not made by Bank of Cyprus” in small text in the header. H2

Typing

  • The empty first row has no placeholders. On desktop, cells look like plain lines until hover. Fix: placeholders in the empty row: “Name as on the account”, “IBAN”, “0.00”, “What the payment is for”. H6
  • After Delete, the focus goes to the Delete button of the next row. A second Enter deletes that row too. Fix: put the focus on the first cell of the next row. H5

Paste and files

  • A paste of many cells into a “Pay from” field puts tabs into the field. Fix: show the paste preview from any field. H5
  • A header that the page does not know, for example “Notes”, makes its column “Skip”. Fix: use the value test for unknown headers too. H5
  • A CSV file has no “Pay from” data. After Open, the account fields are empty. Fix: say this in the export message. H1
  • With errors, CSV is the only way to keep the work for later. Fix: when there are problems, the bar says “To continue later, export CSV”. H3

Errors and warnings

  • The duplicate warning (same IBAN and amount) shows each time, also when the payment is correct. Fix: add “This is correct” to hide it for this file. H3

Phone

  • Search, “Select all” and “Sort” fill the screen above the first payment. Change 2 removes them. H8

Accessibility

  • Controls that show on hover must also show on keyboard focus, and always on touch screens. H4
  • Some text is 11 to 11.5 px (type label, column names). Fix: 12.5 px minimum.
  • “+ More” and “− More” use plus and minus characters in CSS. Some screen readers read them. Fix: use an icon and aria-expanded only.

Not yet done from round 2

  • The footer has no SHA-256 fingerprints yet, and the script and style tags have no SRI.
  • Before the page says “open source”, add a LICENSE file to the repo, for example MIT.
